# howtobe

Пачатковы каркас асабістага сайта на Astro з падтрымкай беларускай, рускай і англійскай моў.

## Запуск лакальна

Патрэбны Node.js версіі `22.23.4` або навейшай.

```sh
npm install
npm run dev
```

Astro запусціць лакальны сервер, звычайна на <http://localhost:4321>.

## Мовы і старонкі

- `astro.config.mjs` — спіс моў, мова па змаўчанні (`be`) і правіла, што ўсе моўныя старонкі маюць прэфікс у URL.
- `src/pages/index.astro` — стартавая старонка `/`: спрабуе вызначыць мову браўзера і перанакіраваць на адпаведную версію; калі мова не падтрымліваецца, выбірае беларускую.
- `src/pages/[lang]/index.astro` — галоўныя старонкі `/be/`, `/ru/` і `/en/`.
- `src/pages/[lang]/awareness.astro` — старонка відэа для кожнай мовы. Крыніца відэа задаецца праз `PUBLIC_R2_MEDIA_BASE_URL`.
- `src/i18n/ui.ts` — пераклады кароткіх элементаў інтэрфейсу і спіс падтрымліваемых моў.
- `src/layouts/SiteLayout.astro` — агульная HTML-абалонка; выставіць правільны `lang` і метададзеныя старонкі.
- `src/pages/` вызначае URL-адрасы сайта; новыя старонкі можна дадаваць у адпаведныя моўныя тэчкі.
- `package.json` — назва праекта, залежнасці і каманды `dev`, `build`, `preview`.

Моўная старонка — звычайны Astro-файл у каталогу мовы. Агульныя пераклады UI змяшчаюцца ў `src/i18n/ui.ts`; змест будучых асобных старонак лепш захоўваць побач у адпаведных тэчках, напрыклад `src/content/about/be.md`, `ru.md`, `en.md`.

У файле `.astro` блок паміж `---` — код, які выконваецца на этапе зборкі. HTML пасля блока становіцца старонкай. Тэг `<style>` у кампаненце дадае стылі толькі для гэтага кампанента; агульныя стылі HTML-абалонкі знаходзяцца ў `src/layouts/SiteLayout.astro`.

## Праверка зборкі

```sh
npm run build
npm run preview
```

Зборка стварае гатовыя статычныя файлы ў `dist/`.

## Публікацыя

Код сайта знаходзіцца ў гэтым рэпазіторыі. Адрас `https://jathpr.github.io/` абслугоўвае асобны рэпазіторый `jathpr.github.io`; яго workflow збірае апошні `main` гэтага праекта.

Пасля змен у `main` запусці workflow **Deploy personal site** у рэпазіторыі `jathpr.github.io` праз GitHub Actions → **Run workflow**. Абнаўленне публікуецца на галоўным адрасе карыстальніцкага сайта.

## Відэа і аўдыё

Для невялікай колькасці відэа без рэкламы можна выкарыстоўваць звычайны HTML `<video controls>` з файламі `.mp4` у Cloudflare R2: убудаваны браўзерны прайгравальнік не дадае рэкламу або старонніх спасылак. Бясплатная квота R2 уключае 10 GB-месяцаў сховішча, 1 млн запытаў Class A і 10 млн Class B за месяц; перадача даных у інтэрнэт бясплатная. Глядзі [актуальныя ўмовы і ліміты R2](https://developers.cloudflare.com/r2/pricing/). Для вытворчага сайта лепш мець уласны дамен, падлучаны да R2; `r2.dev` Cloudflare прызначае для распрацоўкі.

Не рэкамендуецца захоўваць відэа ў Git-рэпазіторыі: GitHub папярэджвае пра файлы ад 50 MiB, блакуе файлы звыш 100 MiB, а GitHub Pages мае мяккі ліміт прапускной здольнасці 100 GB у месяц і ліміт памеру сайта 1 GB. Актуальныя [ліміты GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) і [ліміты вялікіх файлаў GitHub](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github). Выдаленне медыя з Git пазней не памяншае гісторыю рэпазіторыя.

Калі відэа ляжаць у R2, у кодзе застаюцца толькі спасылкі і перакладзеныя назвы. Для шырокай падтрымкі браўзераў варта экспартаваць MP4 з H.264-відэа і AAC-гукам. Калі ў відэа будуць субтытры, можна далучаць асобныя WebVTT-дарожкі для кожнай мовы; відэафайл тады захоўваецца адзін раз. Для аўдыё пазней можна выкарыстаць аналагічны `<audio controls>` і тыя ж медыя-файлы.

### Падключэнне `demo_be.mp4`

Чаканы ключ файла ў bucket: `awareness/demo_be.mp4`. Пасля публічнай актывацыі bucket выстаў `PUBLIC_R2_MEDIA_BASE_URL` у `.env` для лакальнай зборкі або як GitHub Actions variable `R2_PUBLIC_BASE_URL` у рэпазіторыі `jathpr.github.io`. Значэнне — базавы URL bucket без завяршальнага слэша, напрыклад `https://pub-....r2.dev`; сакрэтны API-ключ не патрэбны сайту і не павінен дадавацца ў яго.

Каб падрыхтаваць bucket: ствары ў Cloudflare R2 bucket `howtobe-media`, уключы для яго public access праз `r2.dev`, загрузі відэафайл пад ключом `awareness/demo_be.mp4` і скапіруй выданы `r2.dev` URL у GitHub Actions variable. Пасля змены variable перазапусці **Deploy personal site**. `r2.dev` прызначаны для распрацоўкі і не мае ўласных WAF/cache controls; для доўгатэрміновай публікацыі пазней можна пераключыцца на ўласны дамен.
